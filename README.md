# AI-buddy — MVP для адаптации стажёров

Прототип для хакатона Авито: чек-лист адаптации с дедлайнами, задачи и кабинет наставника, вопросы/ответы, архив обращений, Team Memory с подтверждёнными наставником ответами, AI-разбор ответа, согласование предложенных AI-шагов, имитации корпоративных действий и синхронизация синтетических документов.

**Это демонстрация, не готовый корпоративный сервис.** Нет настоящей авторизации, корпоративных API Авито и автоматической выдачи доступов. Тестовый пользователь: `user_id=1` (без логина/пароля, кабинет наставника открыт как демороль). Не публикуйте этот сервер в интернет и не используйте реальные персональные данные.

## Требования

- Docker Desktop / Docker Engine с Compose для запуска сайта.
- Для локальных тестов: Python и `pytest`, Node.js / npm (версии зависят от `package.json` и `requirements`), SQLite включена в Python.
- Для **живого** AI: действующие `YANDEX_FOLDER_ID` и `YANDEX_API_KEY` в локальном `.env`, квоты и доступ к Yandex Cloud.

## Быстрый запуск без ключей (demo)

```bash
docker compose -p ai-buddy -f compose.yaml up -d --build
curl -s http://localhost:5001/health
```

Откройте http://localhost:5001. Ожидается `mode: demo`, `rag_ready: false`, `status: ok`. В этом режиме работает сценарный чат **без вызова YandexGPT**. Задачи, вопросы, ответы и Team Memory сохраняются в SQLite (Docker volume). AI-разбор ответа наставника в demo отдаёт HTTP 503 — ему нужна живая модель.

## Запуск с YandexGPT и RAG

Скопируйте образец конфигурации, если локального `.env` ещё нет:

```bash
cp .env.example .env
```

Заполните в `.env` переменные `YANDEX_FOLDER_ID` и `YANDEX_API_KEY` настоящими секретами. **Не добавляйте `.env` в Git.** В этой версии предусмотрен отдельный Docker-образ для RAG:

```bash
docker compose -p ai-buddy -f compose.yaml -f compose.rag.yaml up -d --build
curl -s http://localhost:5001/health
```

Для готового RAG ожидается `mode: rag`, `rag_ready: true`, `status: ok`. Если `status: degraded`, то RAG не инициализировался, и сервер переключился в demo: проверьте логи `docker compose -p ai-buddy -f compose.yaml -f compose.rag.yaml logs --tail=80 ai-buddy`. Требуется **отдельно** проверить настоящий вопрос в чате и кнопку «Разобрать ответ с AI»: успешное `/health` не доказывает, что облачный запрос завершится успешно.

> Новый RAG-образ и закреплённые зависимости добавлены для воспроизводимости, но их необходимо проверить командой сборки выше на компьютере команды. Нельзя утверждать, что реальные внешние вызовы протестированы только на основании модульных тестов.

Не используйте одновременно два Flask-сервера на порту 5001. При переключении режимов используйте команды Compose с нужным набором `-f`.

## Проверка основного сценария

1. В кабинете наставника назначьте задачу, описание и дедлайн.
2. В чек-листе стажёра проверьте задачу; задайте вопрос в AI-чате.
3. В разделе вопросов отправьте сообщение наставнику, из кабинета наставника ответьте на него.
4. На отвеченном обращении нажмите «✦ Разобрать ответ с AI» (нужен работающий RAG). AI объяснит ответ и извлечёт шаги. Можно отправить уточнение.
5. Предложите AI-шаги наставнику. Только после отдельного утверждения они добавляются в чек-лист.
6. Опубликуйте ответ наставника в Team Memory. Повторите **тот же вопрос** в чате и убедитесь, что получен проверенный ответ с соответствующим источником.
7. Закройте обращение, найдите его в архиве, отметьте задачу выполненной.
8. Имитацию корпоративного запроса проверьте отдельно: она создаёт запись в SQLite, **не** вызывает реальные корпоративные системы.

## Тесты и покрытие

```bash
python -m pip install pytest pytest-cov
python -m pytest -q --cov=unified_app --cov=demo_chat --cov=db \
  --cov=intent_router --cov=team_memory --cov=mentor_intelligence \
  --cov=knowledge_sync --cov=tickets --cov=routes --cov=rag \
  --cov-report=term-missing
npm ci
npm run test:coverage
```

**Измеренный ранее результат (до этого набора исправлений):** 56/56 Python-тестов, 86% в отчёте Coverage; 44/44 JavaScript-теста, 94,3% строк, 76,96% ветвлений. `rag.py` и `intent_router.py` на том запуске **не были импортированы** — поэтому Python 86% нельзя считать полным покрытием проекта. После правок повторите проверки и приложите обновлённый вывод. Подробнее: `docs/TEST_COVERAGE.md`.

## Код и документация

- `unified_app.py` — единый сервер (выбор demo / RAG, HTTP API).
- `routes/` и `db.py` — задачи и обращения в SQLite.
- `mentor_intelligence.py` — AI-разбор диалога и предложения шагов после ответа наставника.
- `team_memory.py` — подтверждённые знания; **это поиск по словам, не обучение LLM**.
- `knowledge_sync.py` — синхронизация синтетических документов.
- `tickets.py` — закрытие и повторное открытие обращений.
- `frontend/` — интерфейс стажёра и наставника.
- `docs/SDD.md` — спецификация функциональных сценариев и ограничений.
- `docs/RELEASE_CHECKLIST.md` — чек-лист перед сдачей.
