# Team Intelligence — диалоги наставника и синхронизация документов

Дополнение к AI-buddy. Не меняет `rag.py` Антона и существующие маршруты задач.

## Что умеет

1. **«Разобрать ответ с AI»** под ответом наставника. Сервис использует
   оригинальное обращение, ответ наставника и историю уточняющих вопросов
   по этому обращению. Результат показывает объяснение, шаги и то, что
   нужно уточнить. **Требует `AI_MODE=rag` и действующих ключей YandexGPT.**
2. **AI-план на согласовании**. Стажёр может предложить полученные шаги
   наставнику; только подтверждение наставника создаёт реальные задачи.
   Повторное одобрение не создаёт дубликатов. Если наставник редактирует ответ,
   связанная интерпретация и ожидающие планы сбрасываются.
3. **Синхронизация документации**. Источник — тестовые TXT-файлы из
   `mock_corporate_docs/` (по умолчанию) либо заранее настроенный HTTPS JSON API.
   Кнопка запуска в кабинете наставника, периодическое обновление в Docker
   каждые 5 минут при `DOC_SYNC_AUTO=1`.

## Что не подключено

Корпоративные переписки/мессенджеры не подключаются. Тестовые TXT —
**вымышленные**, они не являются внутренними документами Авито. Не загружайте
реальные секреты и персональные данные в демоприложение.

## Контракт опционального API документации

```http
GET https://docs.example.org/api/approved-documents
Authorization: Bearer <server-configured-token>
```

```json
{"documents":[
  {"id":"team_backend", "title":"Backend onboarding", "content":"Проверенный текст инструкции..."}
]}
```

В `.env` (не коммитить):

```text
CORP_DOCS_JSON_URL=https://docs.example.org/api/approved-documents
CORP_DOCS_ALLOWED_HOST=docs.example.org
CORP_DOCS_API_TOKEN=...
DOC_SYNC_AUTO=1
DOC_SYNC_INTERVAL_SECONDS=300
```

Этот endpoint должен возвращать **только разрешённые к публикации документы**.
Ограничения: до 40 документов, до 20 000 символов каждый; HTTPS и совпадение
с разрешённым hostname обязательны. URL не может задаваться стажёром.

## Как RAG подхватывает новые документы

Синхронизатор сохраняет безопасные копии в `knowledge/synced/*.txt` и
сравнивает SHA-256; вручную созданные документы в `knowledge/` не изменяются.
`rag.py` уже читает `knowledge/**/*.txt`. При `AI_MODE=rag` после синхронизации
создаётся **новая цепочка FAISS**, и только при успешной сборке она становится
активной. При ошибке старый объект цепочки остаётся доступен, статус
индексации отражается в `/knowledge-sync/status`.

При `AI_MODE=demo` документ сохраняется локально, но **LLM не вызывается**.
Синхронизированные файлы не попадают в Git по умолчанию. Docker demo
пересинхронизирует исходные TXT при старте фонового цикла/нажатии кнопки.

## Безопасность и ограничения

- Демо-роль наставника **не защищена реальной авторизацией**. Не публиковать
  приложение в интернете с реальными данными.
- AI-интерпретация не становится Team Memory автоматически. Её также нельзя
  считать проверенной наставником.
- Ответ модели не выполняет SQL: реальные задачи появляются только после
  явного решения наставника.
- История уточнений хранится только для соответствующего обращения и
  привязана к тестовому пользователю №1. При изменении ответа история очищается.
- Периодическая синхронизация в процессе Flask подходит только для демо;
  для production следует использовать один отдельный worker/job с очередью.
- Настоящие API-ключи Yandex Cloud нужны локально для `AI_MODE=rag`. Успешный
  pytest не доказывает доступность настоящего YandexGPT.
