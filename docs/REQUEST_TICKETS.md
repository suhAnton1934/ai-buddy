# Обращения как тикеты — demo

## Жизненный цикл

- Новый вопрос: исходный `mentor_questions.status='open'`.
- Наставник ответил: исходный статус `answered`.
- Стажёр или наставник нажал **Закрыть обращение**: запись остается неизменной, а `question_id` записывается в `mentor_ticket_closures` с `closed_at`.
- **Открыть снова** удаляет только запись из `mentor_ticket_closures`, возвращая вопрос в активный список. Ответ остается.
- Архив НЕ удаляет вопросы, ответы, связи Team Memory, AI-разбор или согласованные AI-планы.
- Закрытый вопрос без ответа не учитывается в блоке «Требуют внимания».

## API

- `GET /mentor/tickets?user_id=1` — список `{closed: [{question_id, closed_at}]}`.
- `POST /mentor/tickets/<id>/close`, JSON `{ "user_id": 1 }` — архивировать; повторный запрос безопасен.
- `POST /mentor/tickets/<id>/reopen`, JSON `{ "user_id": 1 }` — снова открыть; повторный запрос безопасен.
- Старые эндпоинты `/mentor/questions`, `/mentor/questions/<id>/reply` и формат `status` не изменены.

## Интерфейс

Фильтры «Активные / Ждут ответа / С ответом / Архив» и поиск по вопросу и ответу у обеих ролей. Изначально показываются 7 записей; «Показать ещё» раскрывает следующие. Обращения не удаляются и не сортируются заново, поэтому кнопки публикации Team Memory и AI-разбора по-прежнему относятся к правильным вопросам.

## Ограничения

Это демонстрационные роли без настоящей авторизации; сервер проверяет только фиксированного стажёра `user_id=1`. Не используйте с реальными корпоративными данными. При тысячах обращений потребуется постраничная выдача и серверный поиск вместо загрузки всей истории.

Не запускайте `docker compose down -v`: это удалит volume с SQLite.
