# AI-buddy — безопасная интеграция настоящего RAG

## Что меняется

Появляется `unified_app.py`: один Flask-процесс обслуживает **frontend, задачи,
кабинет наставника, обращения и чат**. Режим чата выбирается переменной
`AI_MODE=demo` или `AI_MODE=rag`.

- **demo (по умолчанию):** существующий сценарный `demo_chat.py` без облачного API.
- **rag:** существующий `rag.py` Антона, с профилем стажёра и текущими задачами
  из SQLite. Источники ответа показываются по именам файлов.
- Если RAG не смог инициализироваться, сервер *остаётся доступным* в demo-режиме,
  а `GET /health` сообщает `status: degraded` и `mode: demo`.
- Если запрос к живому RAG завершился ошибкой, `/chat` возвращает HTTP 503;
  задачи и кабинет наставника продолжают работать.
- Если запрос явно включает **полное название** одной незавершённой задачи,
  сервер может вернуть `proposed_action`. Изменение в SQLite происходит
  **только после подтверждения** кнопкой; `PATCH /tasks/{id}` выполняется
  существующим Flask API. Это **детерминированное сопоставление задачи**, а не
  полноценный LLM Tool Calling. Не следует заявлять иначе на защите.

Важно: `app.py`, `dev_app.py`, Docker Compose, Dockerfile.demo и `rag.py`
не перезаписываются. Старый демонстрационный запуск остаётся неизменным.

## Установка

1. В чистой ветке после `git fetch origin` и проверки `git status`:

   ```bash
   python ~/Downloads/ai-buddy-safe-integration/install.py --check
   python ~/Downloads/ai-buddy-safe-integration/install.py --apply
   ```

2. Установщик проверяет ожидаемые фрагменты существующих файлов, делает
   резервные копии **вне папки проекта** и при несовпадении прекращает установку.
   Существующие код AI и Docker не удаляются.

3. Запусти тесты:

   ```bash
   npm run test:coverage
   python -m pytest -v
   ```

4. Для безопасного демонстрационного запуска, как раньше:

   ```bash
   docker compose up --build
   ```

5. Для проверки **единого сервера в деморежиме** (отдельно от Docker,
   из корня проекта, в своём виртуальном окружении):

   ```bash
   AI_MODE=demo python unified_app.py
   ```

6. Для проверки **живого RAG**, если у Антона уже установлены и проверены
   зависимости из `rag.py` и есть настоящие ключи (хранить только в `.env`):

   ```bash
   AI_MODE=rag python unified_app.py
   ```

   Затем `http://localhost:5001/health`. Ожидаемо для настоящего RAG:
   `{"status":"ok","mode":"rag","rag_ready":true,"requested_mode":"rag"}`.
   Если режим `demo` и статус `degraded`, причина указана в логах запуска.
   Ключи не должны появляться в репозитории. Не запускай Docker и локальный сервер
   одновременно на одном порту 5001.

**Важно про Docker:** текущий `Dockerfile.demo` намеренно остаётся без AI-зависимостей.
Команда `docker compose up --build` всё ещё запускает старый деморежим.
Дополнительно можно запустить **новый единый сервер в Docker в demo-режиме**:

```bash
docker compose -f compose.yaml -f compose.unified.yaml up --build
```

Для демонстрации живого RAG используется `AI_MODE=rag python unified_app.py`;
для отдельного AI Docker-образа потребуется проверить набор зависимостей и ключи
в окружении Антона.

## Проверяемая демонстрация

1. В профиле задать `Команда = Backend`, `Роль = Backend-разработчик`, `Этап = Первая неделя`.
2. Наставник назначает новую задачу с дедлайном.
3. Стажёр открывает чат и спрашивает `Что у меня сегодня по задачам?`.
4. В RAG-режиме модель получает данные профиля и текущие задачи, отвечает
   на основе контекста и показывает источники из `knowledge/*.txt`.
5. Стажёр пишет `Отметь задачу «Настроить Git» выполненной`.
   Если эта задача ещё не завершена, появится кнопка подтверждения.
6. Только после нажатия кнопки задача становится выполненной. Наставник видит
   обновлённый статус после обновления списка.
7. Стажёр отправляет вопрос наставнику, наставник отвечает.

В demo-режиме старая обработка фраз по Git остаётся сценарной.

## Что ещё НЕ реализовано

- Настоящая авторизация и защита ролей: `DEMO_USER_ID = 1`, любой посетитель
  демосайта может открыть кабинет наставника. **Не разворачивать публично
  с реальными персональными или корпоративными данными.**
- Tool Calling, где именно LLM выбирает инструмент. Сейчас действие предлагается
  серверным сопоставлением точного названия задачи, затем требует подтверждения.
- Настоящая двусторонняя онлайн-переписка, уведомления и история действий.
- Централизованное хранение профиля (сейчас browser localStorage).
- Гарантированное покрытие всех AI-модулей тестами. Новые тесты используют
  подмену RAG, **без реального вызова YandexGPT**.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | Frontend |
| GET | `/health` | Текущий режим чата |
| POST | `/chat` | Chat demo/RAG, единый контракт |
| GET | `/users/1/tasks` | Задачи стажёра |
| PATCH | `/tasks/{id}` | Подтверждённое изменение статуса |
| GET/POST | `/mentor/tasks` | Список/создание задач наставником |
| GET/POST | `/mentor/questions` | Просмотр/создание обращений |
| POST | `/mentor/questions/{id}/reply` | Ответ наставника |

Не использовать примеры онбординга как действительные корпоративные регламенты Авито:
файлы в `knowledge` — синтетические демонстрационные материалы.
